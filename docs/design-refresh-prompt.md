# 実装依頼プロンプト — 「AI が作った見た目」を脱する

> そのままコーディングエージェントに貼って使う指示書。
> 対象: `laravel_app/`（Laravel 12 / Blade / Tailwind v4 / Vite）
> 機能追加はしない。見た目と手触りだけを変える。

---

## 依頼

このアプリの UI は動作としては破綻していないが、**生成 AI が量産する既視感のある見た目**になっている。
「テンプレートっぽさ」を取り除き、業務ツールとして地に足のついた画面にしてほしい。
情報設計・機能・ルーティング・テストの意味は変えないこと。

---

## 現状の診断（この特徴が「AI っぽさ」の正体。裏は取ってよいが再調査は不要）

1. **色が Tailwind の初期値のまま。** `resources/css/app.css` の `--color-brand-*` は `oklch(... 265)`＝
   インディゴ／バイオレット。地色は `slate-50` / `slate-950`。この組み合わせは AI 生成 UI の最頻出パターン。
2. **角丸が大きく、どこも同じ。** `.card` `.field` ボタンが揃って `rounded-xl`。全要素が同じ曲率・同じ影
   （`shadow-sm`）で、要素の重みの差が出ていない。
3. **ランディングがテンプレ構成。** `welcome.blade.php` が「sparkles アイコン入りの丸バッジ →
   キーワードに下線を引いた大見出し → CTA 2 つ → アイコン付き 3 カラムの特徴カード」という、
   AI が必ず出す並び。
4. **余白と文字サイズの階層が弱い。** 見出しから本文までが `text-2xl → text-sm` の 2 段しかなく、
   どの画面も同じリズム。情報密度が低く、業務ツールとして一覧性が犠牲になっている。
5. **コピーがテンプレ調。** 「〜が一目でわかります」「〜を防ぎます」「シンプルな ToDo アプリです」など、
   製品固有の情報を含まない言い回し。
6. **書体が 1 種類。** Noto Sans JP のみで、課題キー（`PROJ-123`）や数値と日本語が同じ表情になっている。

---

## 方針（この順で効く。上から順に実施すること）

### 1. カラートークンを差し替える（最優先・最小コスト）
- `@theme` の `--color-brand-*` から**インディゴ／バイオレット（hue 250–290）を排除**する。
  業務ツールらしい候補は次のいずれか。1 つ選び、理由を PR 説明に書くこと。
  - **インク＋単色アクセント**: 地は限りなく無彩色、アクセントは深い青緑（hue 190–210）か鈍い赤（hue 20–30）
  - **ウォームグレー系**: `slate` を `stone` / `zinc` に寄せ、アクセントは琥珀〜オリーブ（hue 60–110）
- **アクセントは「面」ではなく「線・小面積」で使う。** 現在ブランド色で塗っているボタン・バッジ・
  アイコン背景を見直し、主要 CTA 1 つと現在地表示（下線・左罫）以外はニュートラルにする。
- `.viz` のグラフ配色（`#4f46e5` 系）も新トークンに合わせて更新。ライト `#f8fafc` / ダーク `#020617`
  相当の新しい地色に対してコントラストを再検証すること。

### 2. 形を引き締める
- 角丸は **2 段階だけ**に統一する（小要素 4–6px / 面 8px 程度）。`rounded-xl` / `rounded-2xl` は廃止。
- `shadow-*` は原則使わない。面の分離は **1px のボーダー 1 本**で行う。浮かせるのはメニューとモーダルだけ。
- `.card` は「枠のある箱」から「罫線で仕切られた領域」へ寄せる。一覧はカードを積まず、
  行の間に区切り線を引く（`task-card.blade.php` はこの方向に近いので、他画面をそこへ揃える）。

### 3. 密度とタイポグラフィ
- 見出しは**大きくするのではなくウェイトと字間で立てる**。`text-4xl` / `text-5xl` は
  ランディング以外で使わない。ページ見出しは `text-base`〜`text-lg` + `font-semibold` で十分。
- 一覧系（タスク・バックログ・ボード）は**行の高さを現状より 1〜2 段詰める**。1 画面に入る件数を増やす。
- 欧文・数字用の書体を 1 つ足し、課題キー・日付・数値に当てる（等幅か、少なくとも `tabular-nums`）。
  日本語は Noto Sans JP のまま。ウェイトは 400/500/700 の 3 つに絞る。

### 4. ランディング（`welcome.blade.php`）を作り直す
- **撤去**: sparkles 入り丸バッジ、見出しの下線ハイライト、アイコン付き 3 カラム特徴カード。
- **代わりに置く**: 1 行の説明と CTA、そして**実際の画面（ボードかタスク一覧）のプレビュー**。
  機能の説明文より、実データが入った UI を見せるほうが信用される。
- コピーは製品固有の名詞で書き直す（「ステータス・優先度・期限で整理」ではなく、
  スプリント／バックログ／課題キーなど、このアプリが実際に持っている概念名を使う）。

### 5. 「らしさ」を 1 点だけ作る
全体を均質に整えたうえで、**この製品を思い出せる特徴を 1 つだけ**仕込む。
候補（1 つ選ぶ）: 課題キーの表示処理 / ステータスの色と形の設計 / 空状態の言い回しと絵 / 罫線の使い方。
2 つ以上やらない。あれもこれも効かせると再び「AI っぽさ」に戻る。

---

## 制約

- **機能・URL・フォームの name・バリデーションは一切変えない。**
- アクセシビリティを落とさない: `:focus-visible` のアウトライン、`sr-only` ラベル、
  スキップリンク、`aria-*` は維持。色のコントラストは WCAG AA を満たすこと。
- ダークモード（`html.dark` 切り替え）は全画面で維持。
- 色・角丸・影の値は**必ず `@theme` のトークンか `@layer components` のクラス**に集約し、
  Blade に生の 16 進数やバラバラの角丸を書かない。
- JS 無効でも動く現在の作りを壊さない（フォーム送信ベースのトグル等）。
- 作業後 `php artisan test` が全件 pass すること。`npm run build` が通ること。

---

## 進め方

1. まず `resources/css/app.css` のトークンと `@layer components` だけを変更し、
   **1 コミット相当で全画面の印象が変わる**ことを確認する。
2. 次に「タスク一覧」1 画面だけを上記 2〜3 の方針で仕上げ、**ビフォー／アフターを提示して止まる**。
   方向性の合意を取ってから他画面へ展開すること。
3. 合意後、詳細・ボード・バックログ・分析・プロジェクト設定・認証画面の順に展開。
4. 最後にランディングを作り直す。
5. 変更した画面のスクリーンショットと、判断の理由（なぜその色・その密度か）を添えて報告する。

## やってはいけないこと

- グラデーション背景、グラスモーフィズム、装飾的なアイコン（sparkles / rocket / 🎉）の追加
- 1 画面に 3 色以上のアクセントカラー
- 情報量を減らして余白を増やすだけの「おしゃれ化」
- 新しい UI ライブラリの導入（Tailwind + Blade コンポーネントのまま）
